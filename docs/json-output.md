# Report format (`report.json`, schema 1.0)

`audio-sales-coach analyze` writes `report.json`, `report.md` and `report.html` (click-to-play timeline) into the
`--output` folder. All times are **seconds from the start of the original recording**; every view shares this timebase.

| Key | Content |
|---|---|
| `recording` | absolute path and SHA-256 of the **original** file, codec, channels, duration, `consent` value, `converted_audio` (memory only by default) |
| `layout.result` | `separate_channels` (one speaker per stereo channel), `mixed_mono` (diarized), or `single_speaker` |
| `methods` | how every measurement was made: energy, pitch, pace, pauses, response gap, VAD, speaker turns, event detector + thresholds, transcription |
| `reliability` | speech-to-background dB per channel, noise/compression flags, attribution level, uncertain-speech share, transcription caveats |
| `speakers[]` | `id` (S1, S2), `role` (`salesperson`, `client_in_this_call`, `speaker`, `unknown`), `role_source` (`user`, `channel_map`, `voice_profile`, `none`), talk time/share, `voice_id` scores when profiles exist |
| `role_assignment` | `status` (`needs_user`, `confident`, `not_needed`), command to assign roles, `excerpts[]` (short replayable spans per speaker) |
| `turns[]` | speaker turns with stats (median F0, F0 range, level, estimated syllable rate), pauses, attribution confidence, `uncertain`, `overlap`, `possible_overlap`, words and topics if transcribed |
| `segments[]` | raw speech segments per speaker (channel for stereo) |
| `overlaps[]` | simultaneous speech (separate channels only) |
| `events[]` | detector events: `type` (laughter, breathing, cough_throat), start/end, `score`, AudioSet classes, detector, channel |
| `observations[]` | everything measurable worth reviewing: `talk_share`, `interruption`, `overlap`, `overlap_short`, `possible_interruption` (mono), `response_gap`, `long_pause`, `monologue`, `pace_change`, `pitch_change`, `energy_change`, `laughter`, `breathing`, `cough_throat`, `question` (transcript), `rising_ending` (acoustic). Each has `statement` with `{S1}` placeholders, `measurement`, `method`, `detector`, `score`, `uncertain`, `uncertainty`, `alternatives`, `attribution_reliable` |
| `coaching_notes[]` | see below |
| `views` | `salesperson`, `client`, `combined` (ids of turns/observations/notes per view) - or `speaker_S1`/`speaker_S2`/`combined` until roles are known - or a single `speaker` view for voice messages |
| `council` | `status` (`reviewed`, `skipped`, `not_reviewed`, `error`), `reason`, exit code, verdict status, providers used, per-note claim results, path of the exact `task.json` sent |
| `warnings`, `limitations`, `timings_s` | as named |

## A coaching note

```json
{
  "id": "note-2",
  "timestamp": "00:00:26.2",
  "start": 26.15, "end": 26.55,
  "play": {"recording": "original",
           "uri": "file:///path/to/call.wav#t=24.1,28.6",
           "ffplay": "ffplay -nodisp -autoexit -loglevel error -ss 24.1 -t 4.4 /path/to/call.wav",
           "command": "audio-sales-coach play /path/to/report --note note-2"},
  "speaker": {"id": "S1", "role": "salesperson", "label": "the salesperson (S1)",
              "attribution_confidence": 0.95, "attribution_reliable": true},
  "words": "the client in this call (S2): \"...\" | the salesperson (S1): \"...\"",
  "words_status": "transcribed",
  "cue": {"type": "interruption",
          "description": "The salesperson (S1) started speaking while the client in this call (S2) was speaking (0.4 s of overlap); ...",
          "detector": "per-channel VAD", "method": "simultaneous voice activity on the two call channels",
          "measurement": {"overlap_s": 0.4, "interrupter": "S1", "interrupted": "S2", "earlier_speaker_continued_s": 0.4},
          "score": 0.4, "uncertainty": "none noted"},
  "interaction": "The salesperson (S1) started speaking while the client in this call (S2) was talking about price/budget. Their next turn was a question about contract or cancellation terms.",
  "suggestion": "Let them finish, summarise what you heard in one sentence, then ask: \"Before I answer - what budget range were you planning for this?\"",
  "alternative_explanations": ["The client in this call (S2) may have been finishing anyway", "line delay can make turn-taking look like overlap"],
  "observation_ids": ["obs-2"],
  "uncertain": false,
  "priority": 1,
  "not_inferred": "This note describes what can be heard and measured. It does not say how anyone felt, whether they were truthful, or whether they will buy.",
  "council": {"status": "supported", "claims_checked": 3}
}
```

Notes are generated by deterministic rules (`coaching.py`) and checked by a language guard that rejects emotion,
honesty or buying-intent assertions and pressure tactics. A full real example from a synthetic call is in
`examples/sample-report.json` / `examples/sample-report.md`.
